## 成果・進捗
- これまでにやったことをまとめる
    1. fnの傾向分析の基盤を作った。どの組み合わせでも小さいのが多い。多様性を高めるほどfnの数が減る
    2. バージョン切り替えの状況分析の基盤を作った。信頼度が小さいときに切り替えるとすぐ変わってしまう（必要かもしれないが）。一致度で戻すとyoloだけ使うとすぐもどるし、違うの使うとなかなか戻らなくなる。
    3. cov,cerをfp,fnごとまで実装した。似たモデルばっか使うとcovは低いし、違うの使うとかなり上がる
    4. fnを拾えるような組み合わせ手法として、グループごとの信頼度の和を使ってみた。拾う拾わないの閾値選択でfpfnを調整できる（閾値上げればfp減るがfn増える、閾値下げればfp増えるがfn減る）。
- 課題をまとめる
    1. 一致率でN→1を遷移させると、モデルの多様性が大きいほどNでされることが多くなり、多様性を活かしづらい（計算コストとの両立を考えると）。

    3. 自動運転の状況とマッチしていない。
- 関連研究を集める
    1. https://openaccess.thecvf.com/content/ICCV2025/papers/Yoo_Automated_Model_Evaluation_for_Object_Detection_via_Prediction_Consistency_and_ICCV_2025_paper.pdf
        + 一貫性 (S^C): NMS後の最終ボックスと、破棄された候補ボックス群との空間的な重なり具合を評価する。自信満々に出力しているにもかかわらず、周囲の候補ボックスと位置が不一致な場合、それは誤検出の可能性が高い 。
        + 信頼性 (S^R): 最終ボックスの周囲に、高い確信度を持つ候補ボックスがどれだけ密集しているかをカウントする。多くの「支持者」がいるボックスは信頼性が高いとされる。
    2. https://pmc.ncbi.nlm.nih.gov/articles/PMC12717259/
        + 信頼性トリガーとしてのFeature Disagreement Score (FDS)マルチモーダルな物体検出システムにおいては、異なるセンサー（カメラ、LiDAR、レーダー）間の特徴量の不一致度を示す「FDS」が強力なトリガーとなる 。
        + 低FDS時: 各センサーが整合した情報を出力しているため、単純な特徴融合（Mid-level fusion）のみで高速に処理する 。
        + 高FDS時: センサー間に矛盾がある（例：カメラが霧で視界不良、LiDARが正常）と判断し、各センサーの結果を独立して慎重に評価する「Late fusion」を起動する 。
    3. https://www.mdpi.com/2624-7402/7/11/369
        物体検出の精度と推論速度（FPS）の間にはトレードオフが存在するが、これをパレート最適化によって解決するフレームワークが提案されている 。 具体的には、数種類から十数種類の検出器の中から、現在の天候条件（晴天、霧、雨など）や利用可能なハードウェアリソースに基づき、最適な「軽量アンサンブル」を動的に構成する 。例えば、晴天時は高速なYOLO単体で運用し、雨天時はオクルージョンに強いトランスフォーマーベースのモデルを補助として起動するといった戦略である 。
- 今後の案をまとめる

        + Covが高い,Cerが低い → tpもfpもfnも一致することは少ない

        + Covが低く,Cerも低い → tpが一致することが少なく、fpfnが一致することが多い
